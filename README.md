# dotfiles

Flake-based NixOS system configuration + GNU-stow-managed dotfiles
for the host `ryv` (user `ryv`).

## Layout

Stow packages (`fish/`, `niri/`, `tmux/`, ...) live at the repo root, one
directory per app, mirroring `~` inside. Next to them:

    nixos/            NixOS config; configuration.nix is the entry point
      hardware-configuration.nix   machine-local disks and kernel modules
                      (untracked; generated by nixos-generate-config)
      local.nix       optional machine-local boot entries (untracked)
      modules/        desktop (niri+noctalia), greetd, services, packages
    flake.nix         physical-host and QEMU VM outputs
    flake.lock        pinned nixpkgs and Zen Browser inputs
    rebuild           physical-host nixos-rebuild wrapper

## Approach

Nix installs packages and manages the system. Dotfiles are plain files applied
as symlinks with GNU stow - edit a file, the app reloads it, no rebuild.

## Usage

With the repo cloned at `~/dotfiles`, run from the repo root:

    ./rebuild               # switch physical NixOS host to the locked flake
    stow <package>...       # symlink dotfile packages into ~
    nix flake update        # update locked inputs

## Run as a VM from Arch Linux

Install Nix and QEMU/KVM. Enable the modern Nix CLI and flakes in
`/etc/nix/nix.conf`:

    experimental-features = nix-command flakes

Then run from the repository root:

    nix run .#vm

The first run builds the VM and can take a while. The generated QEMU VM uses
8 GiB RAM, 4 vCPUs, and a 20 GiB disk. Log in as `ryv` with password `ryv`.
The disk image is disposable host-side state and is not part of the flake.

To build without launching:

    nix build .#vm

Delete `ryv-vm.qcow2` to start again with a fresh VM disk.

All packages at once (never `stow */` - that would grab `nixos/`):

    stow alacritty bash fish starship bat git gh ssh tmux nvim zed \
         niri noctalia gtk desktop vesktop btop fastfetch mangohud

## Fresh install

1. Clone to `~/dotfiles`.
2. Set the `ryv` password during installation. The configuration leaves users
   mutable, so the existing password in `/etc/shadow` is preserved.
3. Generate the machine-local hardware module:

       sudo nixos-generate-config --show-hardware-config > nixos/hardware-configuration.nix

4. Optionally create `nixos/local.nix` for extra bootloader entries.
5. `./rebuild`
6. `mkdir -p ~/Projects ~/Pictures/Wallpapers`, then stow all packages (list above).
7. Flatpak: `flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo`
8. Vesktop: settings are pre-seeded by stow. The AskFriday plugin is a custom
   Vencord user plugin and needs a manual Vencord dev install
   (https://github.com/ryvrook/AskFriday - see its README).
